# Day 1 — Scope, starting point and topology

**Budget: 7 task hours + 1 hour buffer.** All checkboxes start unchecked. Complete them only when the work is actually performed.

## A — Scope and reuse (2h)

- [ ] 0-30m: fill D01 with the single-UE goal, explicit non-goals and Friday evidence.
- [ ] 30-60m: inventory existing deployment notes and tooling; put links and exact useful parts in D02.
- [ ] 60-90m: decide what can be reused without adding dependencies. Do not extend existing project features.
- [ ] 90-120m: limit the active backlog to environment, builds, config, baseline and evidence. Mark priorities in D01.

## B — Starting knowledge (2h)

- [ ] 0-30m: draw registration/session flow from memory; label uncertain steps.
- [ ] 30-60m: explain ownership and a state transition in familiar C code. Record its file and revision.
- [ ] 60-90m: explain a Rust error-handling decision and one failure case from your work.
- [ ] 90-120m: trace a Linux packet through interface, routing and firewall decisions. Score each check 0-3 with evidence in D02.

## C — Environment and topology (2h)

- [ ] 0-30m: inventory available Linux host/VM options and access.
- [ ] 30-60m: select one environment; record why it fits and what remains untested.
- [ ] 60-90m: draw UE, gNB, AMF, SMF, UPF and a controlled data endpoint.
- [ ] 90-120m: annotate N2/N3/N4 and the data path with proposed addresses/namespaces; check host/VPN subnet collisions in D03.

## D — Organize the learning record (1h)

- [ ] 0-20m: create private raw-evidence folders and the public template links.
- [ ] 20-40m: write a daily learning note with two known facts and two open questions.
- [ ] 40-60m: update progress only for checks actually completed; generate and review the dashboard.

## E — Review and buffer (1h)

- [ ] Use remaining time for the earliest blocked prerequisite; do not add features.
- [ ] Record hours, observed learning, unresolved question and next action in the daily journal.
- [ ] Review evidence for sensitive data, update progress and publish a small truthful commit.

## Deliverables to show

- [D01: One-page scope and success criteria](../deliverables/D01-scope.md) — Name the one-UE baseline, five backlog items, constraints and Friday proof.
- [D02: Starting knowledge and reuse inventory](../deliverables/D02-starting-point.md) — Record four evidence-based skill checks and specific material worth reusing.
- [D03: Chosen lab environment and topology](../deliverables/D03-topology.md) — Name the Linux path and draw all logical links with collision-checked lab addressing.

## Exit check

A reader can understand the goal and chosen environment; the four starting checks include evidence and uncertainty.

If the gate fails, mark the relevant item blocked/in progress and state why. Do not check the issue complete just because the day ended.
